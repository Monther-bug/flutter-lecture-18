Today's road: console → Android → iOS → package → code. Two packages work together: google_sign_in talks to Google, firebase_auth talks to Firebase. Compare the ID token with a passport stamp: Firebase does not know your Google password; it trusts Google's stamp.

Setup · Android

Android · add the fingerprints, download the settings again

  1. Console → ⚙ Project settings → General → Your apps → the Android app
  2. Add fingerprint → paste the SHA-1 → Save. Again for the SHA-256
  3. In the project folder: flutterfire configure (same project, same platforms; say yes to overwrite)
  4. Stop the app and flutter run again: hot reload does not load new native settings
Terminal · steps 3 and 4
$ flutterfire configure    # yes, overwrite
# stop the app, then
$ flutter run
android/app/google-services.json now has oauth_client entries, including the web client ("client_type": 3). On Android, google_sign_in reads that client ID automatically
Mobile App Development · Lecture 22

Instead of step 3 you can click google-services.json on the same settings page and replace android/app/google-services.json, but re-running the CLI also refreshes the iOS file and firebase_options.dart. When you publish the app one day, the store key has a different fingerprint: add that SHA-1 too.

The package

Install google_sign_in and initialize it once

Terminal
$ flutter pub add google_sign_in          # pubspec: google_sign_in: ^7.2.0
lib/main.dartmain()
Future<void> main() async {
  WidgetsFlutterBinding.ensureInitialized();
  await Firebase.initializeApp(options: DefaultFirebaseOptions.currentPlatform);

  // google_sign_in 7.x: call initialize() exactly ONCE, before anything else.
  // (On the web we use Firebase's signInWithPopup instead, so we skip it.)
  if (!kIsWeb) {
    await GoogleSignIn.instance.initialize();
  }

  runApp(const MyApp());
}

7.x is new

GoogleSignIn.instanceone shared object
initialize()exactly once
authenticate()shows the picker
GoogleSignInExceptionthe errors
kIsWeb (from package:flutter/foundation.dart) is true when the app runs in a browser
Tutorials with GoogleSignIn().signIn() are for 6.x and do not compile with 7.x
Mobile App Development · Lecture 22

New imports in main.dart: package:flutter/foundation.dart and package:google_sign_in/google_sign_in.dart. The package README says that calling other methods before initialize() finishes, or calling it twice, gives undefined behavior: that is why it lives in main().

AuthService · sign in

AuthService · signInWithGoogle()

lib/services/auth_service.dartnew field
final GoogleSignIn _googleSignIn = GoogleSignIn.instance;
inside Future<String?> signInWithGoogle() · try { }
      // 1. Show Google's account picker.
      final GoogleSignInAccount googleUser = await _googleSignIn.authenticate();

      // 2. Take the ID token: Google's proof of who the user is.
      final String? idToken = googleUser.authentication.idToken;
      if (idToken == null) {
        return 'Google did not send an ID token. Check the setup.';
      }

      // 3. Turn it into a Firebase credential and sign in to Firebase.
      final credential = GoogleAuthProvider.credential(idToken: idToken);
      await _auth.signInWithCredential(credential);
      return null;
1authenticate()Returns the chosen account, or throws if anything goes wrong (even cancel)
2authentication.idTokenIn 7.x, authentication is a normal getter: no await. It only has an idToken
3signInWithCredentialCreates the Firebase user the first time, then authStateChanges() tells the AuthGate
Same idea as Lecture 21: null = success, a text = the message to show

Login page · the handler

Login page · _googleLogin()

lib/login_page.dart_LoginPageState
  bool _isGoogleLoading = false; // new

  Future<void> _googleLogin() async {
    final messenger = ScaffoldMessenger.of(context);

    setState(() => _isGoogleLoading = true);
    final error = await _authService.signInWithGoogle();
    if (mounted) setState(() => _isGoogleLoading = false);

    if (error != null) {
      showAppSnackBar(messenger, error, isError: true);
    } else {
      showAppSnackBar(messenger, 'Signed in with Google. Welcome!');
    }
  }
The same pattern as _login() in Lecture 21: messenger before await, mounted after
In build(): final busy = _isLoading || _isGoogleLoading; so only one request runs at a time
busy disables “Forgot password?”, “Sign up” and the Google button; Login uses onPressed: _isGoogleLoading ? null : _login
No navigation code: the AuthGate opens Home by itself

Wrap-up

Summary and questions

Remember

  • Google Sign-In: account picker → ID token → GoogleAuthProvider.credential → signInWithCredential → Firebase user
  • Setup: enable Google · Android SHA-1 + SHA-256, then flutterfire configure again · iOS GIDClientID + URL scheme
  • google_sign_in 7.x: GoogleSignIn.instance, initialize() once, authenticate(), GoogleSignInException
  • Cancel → GoogleSignInExceptionCode.canceled; sign out of both Google and Firebase
  • The same AuthService and AuthGate serve email and Google users
